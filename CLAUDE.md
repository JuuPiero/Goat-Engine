**Nintendo 3DS** (citro3d / PICA200); desktop (wgpu, Vulkan) is the second target and the quick

(F:\Workspace\ts\PiaEngine) — see [ROADMAP.md](ROADMAP.md). The architecture is in
[docs/architecture.md](docs/architecture.md); user docs are in [README.md](README.md) (Vietnamese).

## Gotchas (learned the hard way)
- rust3ds `-sys` build scripts build bindgen allowlists from host paths: on Windows the `\` separators broke the regexes → empty bindings and a missing `libctru_statics_wrapper.c`. The vendored copies use separator-agnostic regexes (`[/\\]`); keep the `[patch]` entries and `exclude = ["third_party"]` (the vendored crates inherit from their own workspace manifests).
- ctru-sys and citro3d-sys both generate `shaderProgram_s` / `shaderInstance_s`: same layout, distinct Rust types — cast pointers between them (pica.rs does).
- `C3D_Material` colors are stored **B, G, R** (a blue material rendered orange until swapped). `C3D_RenderTargetClear` takes 0xRRGGBBAA; texenv constant colors 0xAABBGGRR; C3D_FVec / C3D_Mtx rows are stored w z y x.
- `Mtx_PerspTilt` / `Mtx_OrthoTilt` already rotate for the sideways 3DS screens; render targets are created as (240, 400) / (480, 800 for SSAA) — width and height swapped.
- Textures on PICA: power of two, 8..1024, Morton-tiled 8×8, RGBA8 bytes in ABGR order (`tile_rgba8`).
- hecs components must be `Send + Sync`, hence `Behaviour: Send + Sync + 'static`. Scripts are removed from the entity while they run, which moves entities between archetypes: **ECS iteration order is not stable** — anything order-dependent (draw order!) must sort explicitly (`RenderView::draw_order`).
- Colors are sRGB-authored. The wgpu backend renders to an sRGB surface and linearizes material / light / clear colors (`c4(color, linear)`); the 3DS renders in gamma space with them as is. Vertex colors are not linearized yet.
- The citro3d backend keeps the shader program, light env, the 8 lights and every LUT in a `Box<Fixed>`: citro3d stores pointers to them, so they must never move — LUT caches are `HashMap<_, Box<Lut>>` (a HashMap moves its values when it grows).
- PICA textures are **bottom-up**: `tile_texture` flips rows (the first row in memory is v = 0). Engine UVs are top-left like wgpu; a marker texture (red top half) in the sample checks it.
- PICA light color registers are 8-bit and **wrap** above 1.0 (intensity 2 turned orange pink): `set_lights` divides the color by its largest channel. Lighting is gamma-space and clamps, so strong lights wash out to white sooner than on desktop (expected).
- Depth on 3DS: perspective views use the **W-buffer** (`C3D_DepthMap(false, -1/near, 0)`: depth = 1 near → 0 far, linear) — uniform precision and a linear fog LUT. With the default Z-buffer the whole fog range of a 0.1..200 camera fell into 1–2 LUT entries. Orthographic views use the Z-buffer map (already linear). PICA clip z is [-w, 0] with 0 = far: geometry at exactly z = 0 is clipped (the partial-clear quad sits at -1e-4).
- Partial viewports on 3DS (`C3D_SetViewport`, verified in Citra): GPU x = (1 − (vp.y + vp.h)) × target width, GPU y = (1 − (vp.x + vp.w)) × target height — both screen axes reversed. Partial views are cleared with a quad (depth Always), full ones with `C3D_RenderTargetClear`.
- Spot / distance-attenuation LUTs: distance attenuation through `LightLutDA_Create` with a Rust `extern "C"` callback (`window_attenuation`); spot cones as a signed LUT built by `lut_table(f, signed = true)` (entries 128..255 = negative inputs). The engine's light math (attenuation / spot smoothstep) lives in `goat_gfx::Light` and both backends use it.
- Comparing platforms: build with `GOAT_HELLO_FREEZE=1` (no animation, same frame on desktop and 3DS); `GOAT_HELLO_LIGHT_TEST=1` = no sun, a pure red point + pure green spot (checks light colors). They're `option_env!` in the game, so set them before `goat build`.
- Subsystems are crates exposing a `goat_runtime::Plugin`; games list them in `Game::plugins()` (only listed crates are in a build). Per-frame geometry goes through `update_mesh` + helper entities with a `MeshRenderer`.
- 3DS mid-frame clears: `C3D_RenderTargetClear` is a memory fill that may run before queued draws of earlier views on the same target — clear later views (depth only, partial) with the quad (`clear_viewport`), in command order.
- Owner's order of work (2026-11-24): finish every engine component first (2D, assets, scenes, physics, audio, animation, particles, UI, scripting, editor); platform builders (web...) come last.
- Citra (portable, Vulkan) can die at start-up with `vk::OutOfDeviceMemoryError` while allocating its 512 MB upload buffer when the machine is low on RAM (~2 GB free with the owner's Chrome open): it is the host, not the game — even the devkitPro `fragment_light` example dies then. The SDL frontend has no software renderer (graphics_api = 0 crashes). Retry later; never close the owner's apps.
- Asset keys always use `/`; `.json` assets may carry a UTF-8 BOM (stripped by `AssetIo::read_string`). Asset sample files are generated: `games/hello/assets/models/suzanne.glb` by Blender 3.0 headless (`blender -b --factory-startup --python make_suzanne.py -- out.glb`, factory settings = the owner's Blender config untouched), `textures/logo.png` by System.Drawing.
- GUIDs: every asset has `<file>.meta` (`{ "guid": "<32 hex>" }`, committed); `guid:<hex>[#sub]` keys resolve through `AssetIo::canonical` (lazy scan of `.meta` files, rescanned on a miss) and every `AssetServer` loader canonicalizes first (one cache entry per file). `resolve_relative` leaves `guid:` / `builtin:` references alone. The editor's `Project::sync_guids` (fsops.rs; at startup + debounced on watcher events) creates metas, re-attaches orphaned ones, re-GUIDs duplicates and rewrites references of files moved outside the editor, comparing with `<project>/.goat/guids.json` (gitignored). Scene JSON still stores paths. Tests that copy the sample project must strip or keep metas consistently.
- Prefab overrides: entities spawned from prefabs carry `PrefabSource(id)`; with `set_track_overrides(true)` (editor engine) also a `PrefabBaseline` captured *after* the instance's overrides were applied — save = old overrides composed with `diff(baseline, now)`. "Generated" (not saved) = model nodes + entities with `PrefabSource` under an instance; anything else under an instance is saved with `parent_target`. Spawn prefabs through `spawn_prefab_instance` / `instantiate`, not `spawn_file` (that's for scenes: no PrefabSource on the roots).
- Audio checks without ears: `GOAT_AUDIO_DUMP=x.wav` makes `AudioPlugin` mix on the main thread into a WAV file (rewritten each second) — read its RMS per window to see loops / one-shots / pan. A normal desktop run really plays through the speakers (cpal): keep test runs short.
- Text and sprites share `goat_sprites::{Quad, Batcher}`; dynamic textures use `GraphicsBackend::update_texture` (same size only). Font in the sample: Be Vietnam Pro (OFL, `games/hello/assets/fonts/OFL.txt`).
- Physics bodies are created from the Transform chain on the first fixed step after a Collider appears; the sample's `GOAT_HELLO_FREEZE` doesn't stop physics (screenshots with falling balls differ between runs).
- The 3DS (ARMv6K) has **no 64-bit atomics**: `AtomicU64` doesn't exist there (goat-scene's load counter is an `AtomicU32`). Check new dependencies too (`goat build 3ds` is the test).
- `Time::max_delta` = 0.1: `Engine::frame(0.5, ..)` advances 0.1 s (the first frame advances 0). Tests that compute expected motion must use dt ≤ 0.1.
- Toolchain is rustc 1.97 (don't upgrade the owner's toolchain): oxc ≥ 0.160 needs 1.98, so goat-script-js allows `>=0.100, <0.161` and Cargo.lock holds 0.158 — re-resolve with `CARGO_RESOLVER_INCOMPATIBLE_RUST_VERSIONS=fallback cargo update -p oxc_transformer` (workspace `rust-version = "1.97"`).
- Scripts: every language goes through `goat_script::Api`; add engine features for scripts there (or as an `Extensions` call from the subsystem's crate behind a `script` feature, like goat-animation), then expose them in goat.js (+ a native in goat-script-js/src/lib.rs), goat.h (+ goat-script-native) and tools/goat-cs/Api/GoatEngine.cs. Entities cross to scripts as small handles (f64 / u32 index tables), never as 64-bit ids.
- goat-cs naming: GoatEngine methods → camelCase JS (Debug.LogWarning/LogError are renamed in `JsWriter.Renames`), properties keep their (Unity) names, lifecycle Start/Update/... → start/update...; vector operators need the semantic model (`IsVector`: Vector2/3/4, Quaternion, Color → `.add/.sub/.mul/.div`); names whose first letters are capitals (`HSVToRGB`, `TRS`) need a `Renames` entry or Camel makes them `hSVToRGB`; `Random.Range(float, float)` → `Random.rangeFloat` (JS literals lose the `f`); new goat.js exports must be added to `Exports`. Core API natives (Transform world / children, Camera, Screen, Renderer material properties, Application) live in goat-script `core_api.rs` as `Extensions`; `Transform.position` / `rotation` in scripts are WORLD (composed from local Transforms up the parent chain, so they are right before GlobalTransform propagates); `renderer.material` writes copy the material per entity (`MaterialInstances`) the first time. Rebuild: `cd tools/goat-cs; dotnet build -c Release -o bin` (goat build does it when sources are newer). Generated `X.cs.js` live next to the .cs (the editor regenerates them on change).
- Builds stage assets (`stage_assets` in tools/goat builders/mod.rs): C# → JS, TS → JS, sources dropped. Then `bake_assets` (goat-assets `bake.rs`): every `.json` → binary JSON (`bjson.rs`, magic `GBJ1`; `AssetIo::read_string` turns it back into text, `read_json` / goat-scene `read_file` decode it directly — anything reading asset JSON must go through AssetIo), PNG / JPEG → KTX ETC1 / ETC1A4 (3DS, resized to powers of two; ETC1A4 = private internal format 0x6E1A) or BC1 / BC3 (desktop, `TextureData::bc`, uploaded as is when the device has TEXTURE_COMPRESSION_BC) under the SAME file names: `texture_data` sniffs the magic bytes. `GOAT_NO_BAKE=1` skips it. The 3DS romfs is `target/3ds-romfs` (players/3ds/Cargo.toml), and the 3DS player uses hello-game **without** the `typescript` feature (no oxc on the console).
- Plugins get `early_update` (before fixed steps and behaviours): input actions update there.
- Coroutines (goat-runtime coroutine.rs) run once per frame after the Rust behaviours' `update`, before plugins' `update`. `Time::time_scale` is set through the `TimeScale` resource (applied at the next frame start); `unscaled_delta` ignores it.
- JavaScript hosts: goat-script-js natives are engine-NEUTRAL (`natives()`: `fn(&[serde_json::Value]) -> Result<Value, String>`, only `loadAsset` is per host); Boa (`JsHost`, editor / wasm) and QuickJS (`QjsHost`, feature `quickjs`, players) wrap them — add a native there once. `mod qjs_tests` re-runs the whole tests.rs suite on QuickJS (`cargo test -p goat-script-js --features quickjs`; `bench_hundred_behaviours` is #[ignore]). QuickJS keeps JS values in `Persistent` handles: drop them before the runtime (`impl Drop for QjsHost`) or QuickJS asserts; a reloaded module gets a new name `key?v=N` (QuickJS caches modules forever), resolver / loader strip it. 3DS: rquickjs needs bindgen + devkitARM gcc (env set in tools/goat n3ds.rs `cargo()`: CC / CFLAGS with -Wno-incompatible-pointer-types since newlib int32_t is long, BINDGEN_EXTRA_CLANG_ARGS with newlib includes) and our `pthread_once` (qjs.rs: pthread-3ds lacks it; newlib's would clash).
- Play-mode script tools (goat-script `ScriptDebug` resource, handled at the start of ScriptPlugin::update): `reloads` (hot reload: `ScriptHost::reload` swaps the prototype of running instances), `evals` / `results` (console; goat.js `__console` sets `$sel` / `$scripts` via `__track`), `errors` (Error Pause), `break_requested` (`Debug.break`). Editor side: editor/engine `debugging.rs`, bindings console_eval / console_results / set_error_pause / take_pause_reason, App.tsx syncs only script files while playing.
- Script hosts get `ScriptHost::tick` once per frame between Update and LateUpdate: goat.js `__tick` runs JS coroutines (generators), `Awaitable` promises, UI listeners and tween callbacks. Tween / UI events reach scripts by polling engine calls (`Tween.events`, `UI.clicked`), never by Rust calling into JS.
- Numbers coming from JS arrive in serde_json as f64 (`1.0`, not `1`): extension calls must read ids / counts with `as_f64`, never `as_u64` / `as_i64`.
- Tweens: callbacks run while the `Tweens` resource is taken out; a stand-in resource continues the ids and is merged back (tweens created in callbacks keep their ids). A tween whose target entity is gone is killed.
- goat-ui hit tests use last frame's rects (`UiLayout.rects` + `clips` for masks). Layout groups place children directly in the layout pass (they don't write RectTransforms); Content Size Fitters do write `size`. Quads are clipped on the CPU (axis-aligned) — UI has no rotation.
- Entities in script-call JSON: `goat_script::entity_json(e)` = `{"$entity": bits}`, `entity_arg(v)` reads it. The JS host maps GameObjects (`{_h}`) in arguments to that and `{"$entity"}` results to GameObjects (`fromNative` in goat.js); C callers pass the bits.
- Physics joints / connected bodies are referenced by entity **name** (scenes have no entity references). Joints are (re)built in `sync_joints` each step once both bodies are simulated; removing a body removes its Rapier joints, the map notices (`impulse_joints.get(h)`).
- Mesh colliders: `Shape::Mesh` triangles come from `AssetServer::mesh_geometry` (re-reads the model file: GPU meshes keep no CPU copy), loaded by the plugin before the step into `Physics::meshes`; an empty source = the entity's MeshRenderer mesh key. CharacterController entities get a kinematic capsule body (their Collider component is ignored).
- Unity → GoatEngine coordinates (unity-goat-exporter): flip Z of positions / vectors, (-x, -y, z, w) for quaternions; Unity shapes emit along +Z, GoatEngine's along +Y, so each system's rotation gets ×R_x(-90°). Systems are exported flat (sub-emitters link by entity name). Unity batch runs print licensing errors in the log that don't matter; check for `[goat] exported`.
- Particles: collisions are tested on world-space segments (local systems convert through the emitter matrix); sub-emitter events (`state.events`) are world positions; trails are stored per particle (keep `max_points` small on the 3DS).
- Text input: `Input::text` = characters typed this frame (desktop winit `event.text`); platforms without a keyboard insert `SoftwareKeyboard` (goat-runtime) and serve `request` after the frame (3DS: swkbd applet, blocking).

## Editor (editor/)
- Tauri 2 shell (`editor/src-tauri`, crate `goat-editor`: file ops in `fsops.rs` with tests, commands in `main.rs`, watcher → `assets-changed`) + React UI (`editor/src`, Vite, dockview-react docking, layout saved in localStorage) + the engine as wasm (`editor/engine`, crate `goat-editor-engine`: `core.rs` portable + tested with NullBackend, `web.rs` wasm-bindgen API).
- Editor views: the Scene canvas is WgpuBackend surface 0, the Game canvas a second surface (`add_surface` / `use_surface` swap the active surface's parts in and out of the backend's fields — render code is unchanged). `EditorEngine::frame` runs `EditorCore::frame_pass` twice (Game, then Scene); only one pass simulates (the game pass while playing, the scene pass in edit mode), the other `render_only`s. `Engine` re-reads `gfx.displays()` every frame for that. Gizmo / overlay code must `propagate_transforms` first (else they trail moved objects by a frame).
- Low-level graphics (like PiaEngine §4a): goat-gfx `create_render_target` / `read_pixels` / `texture_size`, `RenderView.target` (views into targets draw first: wgpu one pass per target; citro3d VRAM texture + `C3D_RenderTargetCreateFromTex`, untilted projections `into_texture`, FCRAM / smaller fallbacks), `DrawItem.color` (property block / instance colors). goat-runtime `graphics.rs`: frame-scoped `GraphicsQueue` resource (drawMesh, Debug lines, GL prims, blits) cleared in `Engine::frame` and turned into items / extra views by `graphics::apply` right after `extract_camera_views` (lines = camera-facing quads per view; screen-space GL and screen blits only when `game_screen`, i.e. not the editor Scene view); `PostEffect` re-targets the camera into pooled RTs and inserts blit views. Textures are named by KEY everywhere (scripts' textures = `runtime:…` keys registered in AssetServer); `.renderTexture.json` loads through `AssetServer::texture`. Render-texture cameras also draw beside the editor's `view_camera`, without layer 31. Script natives: goat-script `graphics_api.rs`; JS in goat.js (Texture2D pixels bottom-up in JS, natives flip; bytes cross as base64). citro3d: never `C3D_TexBind(1|2, NULL)` (it reads tex->type: address 0xC) — use `unbind_texture`; QuickJS's `pthread_mutex_init(m, NULL)` goes through `goat_pthread_mutex_init` (CFLAGS define in n3ds.rs) because pthread-3ds dereferences attr.
- Several scenes (goat-scene `scenes.rs`): entities spawned by a scene load get `SceneMember(handle)`; `LoadedScenes` resource = list + active + events; `DONT_DESTROY_ON_LOAD` = u32::MAX; entities without a member (made at run time) belong to the active scene (`scene_of` climbs parents). Loads / unloads from scripts are `SceneOps` with ids, run at the end of `late_update` (ScenePlugin); `load_scene` = `scenes::load` (Single keeps DontSave + DDOL). Script natives in goat-script `scene_api.rs`; JS `Scene`, `AsyncOperation` (thenable, completed in `__tick`), events polled only once someone listens (stale ones dropped). Editor: `HierarchyRow.scene` + `play_scenes()` → one header per scene while playing.
- Script gizmos: `Gizmos.lines` / `Gizmos.label` natives fill goat-runtime `GizmoQueue`; Play: the editor inserts `DrawGizmos { selected }` into the play engine and ScriptPlugin calls onDrawGizmos(Selected) after LateUpdate; Edit: `draw_edit_gizmos` (editor scripting.rs) makes throwaway instances of scripts whose SOURCE contains "onDrawGizmos" (registers the core Extensions on the edit engine). The editor merges the queue into its gizmo mesh + overlay labels.
- No trailing gizmos (owner noticed twice): overlays drawn in JS must run from `afterFrame` (viewport.ts, right after `eng.frame`), never their own requestAnimationFrame (that ran before the engine's); in Play the Scene pass does `Engine::step` (simulate, no draw) → helpers → `render_only`.
- Handles while dragging: `gizmo_frame` keeps the press's axes / size (the drag math) but moves the origin with the objects; the Inspector re-reads during the drag (throttled `hierarchyRev` bump in Viewport.tsx).
- Vite dev server: two writes of one file in quick succession (scripted edits) can leave the dev server serving the FIRST version (its watcher misses the second) — touch the file again before testing (symptom: code in the file that the page doesn't run).
- Decorators: oxc compiles TS legacy decorators with External helpers (`babelHelpers.decorate`, defined in goat.js) — ts.rs; the `goat` CLI compiles TS for builds with the same function (rebuild `goat.exe` after changing ts.rs, or the 3DS build ships untranslated `@field`). - Shaders (crates/goat-shader): `.shader` = ShaderLab + HLSL subset → `shaderlab.rs` (properties, state), `hlsl.rs` (lexer / preprocessor / parser), `wgsl.rs` (type-checked WGSL + entry points `fs_custom` / `vs_custom`); `prelude.wgsl` is shared with the standard material (goat-gfx-wgpu `standard_wgsl()` = prelude + standard.wgsl: keep the lighting in `goat_light` / `goat_fog` so both agree). HLSL matrices are stored transposed: `mul(a, b)` → `b * a`. Material params: 16 vec4 slots (`goat_params`, material bind group binding 5) + 4 texture units (bindings 0, 2, 6, 7); `MaterialDesc.shader_color_slots` marks sRGB colors. - 3DS shadow map (pica.rs `shadow_pass`): programs 3 = receive.v.pica (standard + texcoord0 / texcoord0w from `lightMtx`, base texture on unit 1) and 4 = shadow.v.pica (`lightMvp`, outpos.z = −depth). PICA rules (from Azahar's sw_rasterizer / sw_framebuffer): in GPU_FRAGOPMODE_SHADOW the fragment depth (DepthMap w-buffer, −1 scale → depth = −z) is written only when nearer than the stored 24-bit depth, TEV green = intensity (0 = depth only); clear the map to 0xFFFFFFFF; sampling compares |texcoord0w| − bias against the stored depth (orthographic: s, t not divided), result multiplies the lights whose shadow bit is on (`C3D_LightShadowEnable`) when `C3D_LightEnvShadowMode` has PRIMARY / SECONDARY and ShadowSel = unit 0. Materials that use unit 0 otherwise (cube maps, emission maps, TEV programs) set shadow mode 0. `GOAT_3DS_DEBUG=noshadow` skips the pass.
- 3DS shaders: goat-shader `pica.rs` lowers frag / surf symbolically to `Ir` (at compile, `Shader::pica` / `pica_error`), `plan` folds the material's values and allocates `goat_gfx::TevProgram` stages (buffer for two computed operands, stages 0–3 only); goat-assets sets `MaterialDesc::tev` when `create_shader` is Unsupported; citro3d `set_tev_material` programs it (grading in the next free stage). Any change to the planner: the `tev_*` tests compare `pica::simulate` with `pica::eval` on random inputs. Build a 3DS test scene with `GOAT_START_SCENE=scenes/x.scene.json goat build 3ds` (romfs staged by `goat`, not by `cargo 3ds`) — rebuild without it afterwards, the owner runs out/3ds/goat-hello.3dsx.
- Shader keywords / passes: `compile_variant(src, keywords)` preprocesses every pass with the chosen keyword of each `multi_compile` / `shader_feature` group (read first without keywords); passes share one parameter layout (properties, then uniforms any pass declares). goat-assets caches variants as `path|KW KW` and GPU programs as `variant#pass`; extra passes are their own materials chained by `MaterialDesc::next_pass` (both backends draw the chain right after the item; wgpu sizes its uniform buffer per pass). Material keywords = `"keywords"` + `Property::keyword_for` (Toggle / KeywordEnum). On the 3DS, `clip` becomes `TevProgram::alpha_test` (the clipped value goes to alpha when opaque) and uv tiling `TevProgram::uv` → the standard vertex shader's `uvST` uniform (re-uploaded on program switches: uniform registers are shared). A stage holds ONE constant: fusing `a × K1 + K2` into MultiplyAdd is refused (`one_constant`).
- Animation window (editor/src/panels/AnimationWindow.tsx, engine editor/engine/src/animation.rs): `anim_preview` samples a clip onto the edit world and keeps the transforms / components it started from (`anim_preview_end` restores; `save_scene` swaps them back while serializing, so Play / Save never keep previewed values).
